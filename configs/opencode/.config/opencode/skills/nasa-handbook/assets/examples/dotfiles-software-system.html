CONFIGURATION DEPLOYMENT SUBSYSTEM
2.1.1

INTRODUCTION.

The configuration deployment subsystem places one Git repository's configuration into $HOME by two paths. Public files, in 21 stow packages under configs/, are linked: each is a symbolic link back into the repository, so an edit there is live at once. Secret files are vault-encrypted and are copied, decrypted, by Ansible (figure 2.1-1).

2.1.2

FUNCTIONAL DESCRIPTION.

MAKE INSTALL runs ansible-playbook on localhost with --ask-become-pass and --ask-vault-pass. Ansible gathers facts and runs main.yaml in order (figure 2.1-2): vaulted env, SSH and Git files are copied, one OS package list installs tools, and the stow task links every package into $HOME. Other targets pass one tag; MAKE STOW calls stow without Ansible.

2.1.2.1

Package List Selection.

Each of the three OS package lists carries tag always, so it loads on every run whatever the tags, and a when test on the gathered facts keeps one: Ubuntu or Pop!_OS, apt; Archlinux family, pacman; Darwin, the Homebrew role.

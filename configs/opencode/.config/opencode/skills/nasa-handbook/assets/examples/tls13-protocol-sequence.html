TLS 1.3 HANDSHAKE PROTOCOL
2.7.1

INTRODUCTION.

The TLS 1.3 handshake protocol (RFC 8446) establishes shared traffic keys between a client and a server. The client sends its key share in the first flight, so the server derives handshake keys on receipt; every message after ServerHello is encrypted, and a full handshake completes in one round trip (figure 2.7-1).

2.7.2

FUNCTIONAL DESCRIPTION.

The client sends ClientHello in plaintext with supported_versions, key_share and signature_algorithms. The server answers with ServerHello and its own key_share; both sides compute the (EC)DHE secret. Under handshake keys the server sends EncryptedExtensions, Certificate, CertificateVerify and Finished. The client verifies them, returns Finished and switches to application keys (figure 2.7-2).

2.7.2.1

Key Schedule Chaining.

HKDF-Extract chains three secrets: Early Secret (input PSK or 0), Handshake Secret (input (EC)DHE) and Master Secret (input 0). Derive-Secret(., "derived", "") links each stage to the next.
